# Step 2.2: extract DatasetTopbar + EmptyState from routes/datasets/[name]/+page.svelte

**Context:** Second sub-step of `Phase 2: extract sub-components from oversized files` in `plans/archive/frontend-component-organization.md`. The 631-line `+page.svelte` had two obvious extractions: the `<Topbar>` block (~80 lines of markup) and the "No images found" empty state (~15 lines). The plan also called for extracting the captioning-done effects into a runes module — **skipped that part, see below**.

**Decisions:**

- **`routes/datasets/[name]/DatasetTopbar.svelte`** (123 lines) — the entire `<Topbar>` content. Props mirror what the page already derives: `datasetName`, `currentDataset`, `isBatchCaptioning`, `isStopping`, `captionPct`, `captionProcessed`, `captionTotal`, `isRefreshing`, `canUpload`. Events: `onrefresh`, `onupload`. Co-located (next to the page) per the plan — single-consumer component.
- **`lib/components/ui/EmptyState.svelte`** (26 lines) — generic "empty list" primitive: `title`, optional `description`, optional `actions` snippet, optional `class`. Used by the dataset detail page here; the dataset listing and templates listing pages have similar markup that could adopt this in a future PR.
- **`+page.svelte`**: 631 → 572 lines (-59).

**Skipped: `useCaptioningEffects.svelte.ts`.** The plan suggested extracting the two captioning-related `$effect` blocks (job-id registration + done-toast firing) into a runes module exposing `useCaptioningDoneEffect(datasetName, onRefresh)` and `useCaptioningJobIdRegistration(datasetName)`. **Implemented and then reverted.** Reason:

- The `$store` auto-subscribe syntax does **not** work inside `.svelte.ts` files — Svelte only transforms it in `.svelte` files. The runes module had to use `captioningStatus.subscribe(...)` inside the `$effect`, plus `get(lastStartedJobId)` to read the job-store value.
- Svelte 5 captures the initial value of `$state`/`$derived` arguments at call time, so the helpers had to accept `getDatasetName: () => string` instead of `datasetName: string` (with a Svelte warning if you don't).
- Net effect: the extracted version was 79 lines (mostly comments and module boilerplate) but only saved ~30 lines in the page, so the page grew overall (+49 net) **and** the reading experience was worse — the `get()` + `subscribe()` + getter-arg pattern is more complex than the original `$captioningStatus` auto-subscribe inline in the page.
- The user flagged this on review ("idk about useCaptioningEffects. how does that help? seems harder to understand imo") and asked to revert. Reverted — the file is gone and the page has the original two `$effect` blocks back. The remaining `DatasetTopbar` + `EmptyState` extractions are the clean win.

**`EmptyState` adopted in 3 places** (per user request after first review): `routes/datasets/[name]/+page.svelte` (the "No images found" state inside the grid), `routes/+page.svelte` (dataset listing), `routes/templates/+page.svelte` (templates listing). Both listing pages dropped the redundant `py-12` class since the `.empty-state` CSS class already applies it. The SidePanel "Select an image to view details" placeholder was considered but rejected — it's a different style (1-line, no title/description, no action) and doesn't fit the EmptyState shape.

**Plan deviation:** the plan estimated the page at ~350 lines after extraction; actual is 572. The bulk of the difference is the data-loading effects (`loadInitial` + `loadMore` + the dataset-name change effect + the dataset-list refresh + the onMount fetch) and the captioning effects — none of which the plan's extractions target, and all of which are page-specific flow that's awkward to move without forcing a more comprehensive refactor.

**Verification:** `svelte-check` → 0 errors / 0 warnings. `vite build` → success. `eslint .` → clean.
