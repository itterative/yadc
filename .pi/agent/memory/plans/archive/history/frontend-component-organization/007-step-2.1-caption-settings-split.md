# Step 2.1: split CaptionSettingsPanel into host + TemplateSection + OverridesSection

**Context:** First sub-step of `Phase 2: extract sub-components from oversized files` in `plans/archive/frontend-component-organization.md`. The 683-line `CaptionSettingsPanel` (post-Phase-1) was the largest non-page file in the project. The plan called for splitting the template section (~150 lines) and overrides section (~50 lines) into separate components.

**Decision:**

- **TemplateSection.svelte** (263 lines) — owns all template state. API is 5 bindable props (`selectedTemplate`, `templateContent`, `templateDirty`, `isNewTemplate`, `newTemplateName`) that the host reads to assemble `CaptionOptions` + persist to `captionSettings`. The host writes back via bindable (from localStorage restore + dataset default prefill). Plus 1 read-only prop `datasetDefaultTemplate` for the diff dot. Owns its own `$effect` to load the template list on mount and another to load the selected template's content. Reuses the same `loadTemplateList()` pattern (may seed `'default'` if list has it and nothing is selected).
- **OverridesSection.svelte** (66 lines) — purely presentational. `expanded` is bindable. Receives `overrides` array (read-only) and `onReset(field)` / `onResetAll()` callbacks. Exports an `OverrideItem` interface from `<script module>` so the host can type the array.
- **CaptionSettingsPanel.svelte** (441 lines after split, was 683) — host keeps state, persistence, start/stop logic, and the diff-tracking `overrides` array. The two extracted sections render as siblings in the scrollable content area. The diff dot logic for templates stays in the host because `templateOverridden` is also needed by the `overrides` array.

**Deviations from the plan:**

- The plan estimated the host at ~200 lines; actual is 441. The bulk is the per-field `loadDatasetDefaults` (8 `if (saved.X === HARDCODED_DEFAULTS.X)` checks) and `resetField` (8-case switch) plus the `overrides` derived (8 `if` blocks). The original 683 → new 441 is a 242-line reduction (35% smaller). The plan's ~200 estimate assumed the per-field copy-paste could be data-driven; that's a bigger refactor (consolidating 8 separate `$state` variables into one object) that wasn't strictly needed for this step. The file is now cohesive — the host is about caption settings orchestration, the sections are about their respective UI concerns.
- `resetField` signature changed from `(field: OverrideableField)` to `(field: string)` to match the section's `OverrideItem.field: string` type. The switch still covers all 8 known cases plus a no-op default for forward-compat with new diff types.

**Race-condition note:** TemplateSection's mount effect calls `loadTemplateList` independently from the host's `loadDatasetDefaults`. The two async writes to `selectedTemplate` race, but `loadDatasetDefaults` always wins for the final value because (a) it fires after the host's localStorage restore, (b) it has the same emptiness precondition (`saved.selectedTemplate === HARDCODED_DEFAULTS.selectedTemplate`), and (c) both functions are idempotent. The intermediate `selectedTemplate = 'default'` from `loadTemplateList` is harmless even if visible briefly.

**Verification:** `svelte-check` → 0 errors / 0 warnings. `vite build` → success. `eslint .` → clean.
