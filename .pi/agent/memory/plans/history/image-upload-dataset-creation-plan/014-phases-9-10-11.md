# Phases 9–11: Validation, Flatten, and UploadResult

## Summary

Implemented content validation, flat folder upload enforcement, and structured upload response with warnings.

## Phase 9: Validate uploaded file contents

- **Images**: `Image.open(stream).verify()` — skips corrupted/truncated images
- **TOML / `.toml~`**: `toml.loads(content.decode("utf-8"))` — skips invalid TOML
- **`.txt`, `.draft~`, `.history~`**: No content validation (plain text)
- **Orphan sidecars**: After collecting all files, checks that each sidecar has a matching image with the same stem in the same directory. Skips orphans with warning.
- If all files are filtered out, raises `ValueError("No valid files to upload after validation")` and cleans up.

## Phase 10: Flatten uploads — no recursive folder scanning

- **Backend**: Skips files with `len(pure.parts) > 2` (nested beyond `folder/file`). Only root files and single-level folder files are accepted.
- **Frontend `FileDropZone`**:
  - `collectFilesFromEntry()` (drag-and-drop): Only collects direct file children of dropped directories. Subdirectories are silently skipped.
  - `handleFileSelect()` (`webkitdirectory`): Filters out files where `webkitRelativePath` contains more than one `/`.

## Phase 11: Upload response with warnings

- Added `DatasetUploadResult` dataclass: `{dataset: DatasetInfo, warnings: list[str]}`
- `create_dataset_from_upload()` returns `DatasetUploadResult`
- API endpoint serializes it via `jsonify_dataclass()` (nested dataclass → dict via `dataclasses.asdict()`)
- Frontend `uploadDataset()` returns `Promise<DatasetUploadResult>`
- `AddDatasetDialog` shows `toast.warning()` with skipped file details when warnings exist
