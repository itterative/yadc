# Step 1.3: promote CaptionSettings to lib/components/caption/

**Context:** Third sub-step of `Phase 1: file moves` in `plans/frontend-component-organization.md`. The only step in Phase 1 that moves a **route file** to `lib/` — a promotion, not a same-folder rename.

**Decision:** Renamed the file to `CaptionSettingsPanel.svelte` (folder convention: `<Domain><Feature>.svelte` so the host file is the natural entry point) and updated both the import and the in-template usage in `SidePanel.svelte`. Did NOT keep the import alias as `CaptionSettings` — the rename makes the file identity clearer and the diff is still small (2 lines in `SidePanel.svelte`).

**Result:**
- `routes/datasets/[name]/CaptionSettings.svelte` → `lib/components/caption/CaptionSettingsPanel.svelte`
- `routes/datasets/[name]/SidePanel.svelte`: import + 1 usage updated

**Why promote, not co-locate:** `CaptionSettings` exposes caption-flow widgets (env, options, template, overrides) that belong to the **captioning** domain, not the dataset route. The route only consumes it; the widget logic is domain-shared. Per the "promote on second use" rule, the file becomes a `lib/` component as soon as it's extracted from a single-route context — and the panel's role is the canonical captioning flow, used by the only current consumer (the dataset detail page) but conceptually domain-level.

**Defer:** File content is unchanged. The Phase 2 split (host + `TemplateSection` + `OverridesSection`) is still planned.

**Verification:** `svelte-check` → 0 errors / 0 warnings. `vite build` → success.
